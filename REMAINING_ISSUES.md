# OpenImageIO Remaining Work

The package has a verified five-format baseline, but it is not complete
ImageIO parity. Work is prioritized by correctness and independent evidence.

## Status

| Area | Verified | Remaining |
|---|---|---|
| PNG/JPEG/GIF/BMP/TIFF pixels | Native, browser, and Apple ImageIO external checks | Expand malformed-input, uncommon color-model, and bitstream coverage |
| Metadata | EXIF/IPTC/GPS/XMP APIs and common round trips | Broader maker-note and cross-encoder fixtures |
| Incremental sources | Core state transitions | Progressive behavior across more real-world streams |
| Auxiliary images | JPEG HDR gain-map path | Depth, disparity, portrait matte, and semantic mattes |
| WebP | Container/type recognition only | A conforming VP8/VP8L pixel codec before advertising decode or encode |
| HEIF/AVIF/RAW | Constants and metadata definitions where useful | Pixel codecs remain intentionally unsupported |

## Next Milestones

1. Add a corpus generated by independent encoders for uncommon PNG, JPEG,
   GIF, BMP, and TIFF variants.
2. Add fuzz/property tests for bounds checks, allocation limits, truncation,
   and malformed metadata.
3. Validate incremental loading semantics against Apple ImageIO for each
   advertised format.
4. Implement additional auxiliary image types only with external fixtures and
   browser execution evidence.
5. Treat WebP as a new codec project: implement and externally validate VP8,
   VP8L, alpha, animation, and failure semantics before exposing its UTI.

## Definition of Done for a New Format

A format is not complete when a header is recognized or a round trip succeeds
only through the package's own encoder and decoder. It is complete enough to
advertise only after independent decode and encode conformance, malformed-input
coverage, WASM compilation, and real-browser execution all pass.
